## 1. 演示脚本（3 分钟，写给评委看的那条路）

1. **0:00 标题**：夜色里的窑房剪影，窑门透出一点红光。字幕：*一窑火，十二个时辰，一片瓷告诉你火候。*
2. **0:12 夜一 · 满窑**：屏幕是窑的剖面：左边火膛，中间九个窑位（窑头/窑身/窑尾 × 上/中/下），右边烟囱。下方托盘里五件影青。
   鼠标点起一件，九个窑位上浮出预判：**窑头「过火」、窑身「合适」、窑尾「生烧」**。玩家把影青放到窑身。点「封窑」。
3. **0:40 烧窑**：窑门关上，火膛亮起。右侧一条火路（本窑要走的曲线），一条白线是你的火。
   按住「投柴」，火色从暗红转橙；松开就掉温。风门开大开小，火色跟着变。
   走到第三个时辰，事件卡弹出：**柴房返潮**——「用湿柴（省 8 把，升温慢）」/「换干柴（多花 8 文）」。
4. **1:20 火照子**：峰值前，点「拉火照子」。一片瓷从火眼里被钩出来，特写：釉面还哑着，边上挂着一粒未熔的釉珠。读数：火候 0.42，**未熟**。玩家回去补柴。
5. **2:00 开窑**：窑门开，热浪。五件瓷器一件件出窑：四件「合格」、一件「精品」（釉面匀亮），订单达成。铜钱 +42，声誉 +3。
6. **2:30 夜二**：托盘里混了青花与影青，火路抬高。同一套操作，但这次放错一件，出窑是「过火·流釉」。
7. **2:50 收尾**：三夜打完的结局卡 + 一行：*把桩师傅没有温度计，他有一片瓷。*

每一步都只需要鼠标（或键盘）一个动作，没有菜单、没有教程弹窗、没有加载。

## 2. 核心循环

一局 = 三夜。每夜三段：

### 2.1 满窑（load）

- 窑室剖面 3 列 × 3 行 = 9 个窑位。火位系数 `factor = colF[c] * rowF[r]`：
  - `colF = [1.16, 1.00, 0.86]`（窑头、窑身、窑尾）
  - `rowF = [1.06, 1.00, 0.92]`（上、中、下）
  - 取值域 0.7912 ～ 1.2296。
- 每件瓷器有一个火候带 `[lo, hi]`，成品火候 `eff = peak * factor`：
  - `eff > hi + 0.02` → **过火**（流釉、变形）
  - `eff < lo - 0.02` → **生烧**（发色灰、釉不熔）
  - 否则按贴合度分**合格 / 精品**（`q = 1 - |eff-mid|/half`，`q ≥ 0.80` 为精品）。
- 选中一件时，九个窑位按**本夜火路峰值**实时预判并上色。玩家据此押火位。

### 2.2 烧窑（fire）

12 个时辰，每时辰 18 秒（一夜 216 秒）。状态量：

| 量 | 含义 | 范围 |
|---|---|---|
| `temp` | 火候（归一化温度） | 0 ～ 1.05 |
| `fuel` | 火膛里的柴 | 0 ～ 1.2 |
| `wood` | 本夜剩余柴（把） | 0 ～ 120 |
| `vent` | 火眼开度 | 0 ～ 3 |
| `stress` | 脱轨累积 | ≥ 0 |

每 tick（dt 秒）：

```
airflow = 0.55 + 0.22 * vent          // 0.55 ～ 1.21
burn    = min(1, fuel) * airflow
fuel    = max(0, fuel - burn * 0.09 * dt)
temp   += (burn * 0.34 - (0.30 * temp + 0.04)) * dt
```

- 按住「投柴」：`fuel += 0.55 * dt`，`wood -= 0.80 * dt`（约 1.4 把/秒的消耗换 1 秒的旺火）。
- 停车（不投柴）时 `fuel` 以 `burn*0.09` 衰减，约 10 秒掉一半。
- `stress += max(0, |temp - target| - 0.05) * dt`；本夜结算据此扣声誉。

**火路**：每夜给定 12 个目标点（线性插值成连续曲线）。峰值 `peak` = 第 9～11 时辰的实际平均温度。

**事件**：每夜在固定时辰弹一张卡（夜一 1 张、夜二 2 张、夜三 3 张），两个选项各有数值后果，选完才继续走时间。

**火照子**：3 次。拉出瓷片看特写：釉面熔化程度 = 当前 `temp` 与该夜峰值的比；同时给一句人话（未熟 / 正到 / 过火）。用尽后按钮禁用。

### 2.3 开窑（open）

逐件出窑，每件给一个判定与一句师傅点评，落在瓷片标签上。全部出完后进结算：铜钱、声誉、订单达成、夜次推进。

## 3. 数据

三夜（难度递增）：

| 夜 | 名 | 瓷器 | 火路峰值 | 事件 | 说明 |
|---|---|---|---|---|---|
| 一 | 试烧 | 5 件影青 | 0.50 | 1 | 教学：只有一种瓷器，随便放也多半合格，但放错就生烧 |
| 二 | 官窑订单 | 影青 3 + 青花 4 | 0.60 | 2 | 两种火候带，必须分窑位 |
| 三 | 贡瓷 | 青花 4 + 霁红 3 | 0.68 | 3 | 带子窄，升温过快会惊釉 |

订单（每夜 1–2 条）：如「交 3 件合格青花」→ 达成加钱与声誉。

## 4. 验收条件（可判定）

| 编号 | 条件 | 怎么验 |
|---|---|---|
| AC-1 | 打开页面 3 秒内出现标题页，无需登录、无网络请求 | e2e：`page.goto` 后 3s 内 `#stage` 有内容；`page.on('request')` 只允许同源静态资源 |
| AC-2 | 满窑有 9 个窑位，点瓷器再点窑位可放置；同一窑位不能重复放 | e2e：点第一件 + 第 5 格 → 该格出现瓷器；再点第二件 + 第 5 格 → 不变 |
| AC-3 | 选中瓷器时窑位显示过火/合适/生烧预判 | 单测 `forecastSlot()` 三个分支各一例；e2e 检查 `.slot[data-verdict]` 出现 |
| AC-4 | 投柴、火眼、火照子三个操作都在，且状态随之变化 | e2e：按住投柴 2 秒后 `window.__game.temp` 上升；火眼切到 3 后 `vent===3` |
| AC-5 | 温度模型：满柴满风趋近 1.0；断柴 20 秒后下降 ≥ 0.15 | 单测 `stepFire()` 两条 |
| AC-6 | 事件卡在指定时辰弹出，两个选项各有后果 | 单测 `applyChoice()`；e2e 检测事件卡出现并可点 |
| AC-7 | 火照子 3 次，用尽后禁用 | e2e 连续点 3 次后按钮 `disabled` |
| AC-8 | 十二时辰走完自动进开窑 | e2e 用调试接口快进 12 时辰 → `phase==='open'` |
| AC-9 | 开窑每件都有判定，且过火/生烧/合格/精品/窑变可复现 | 单测 `evaluateKiln()` 用固定种子覆盖 5 种判定 |

| AC-11 | 键盘可完成全部操作：空格投柴、1–4 火眼、Q 火照子、Enter 继续 | e2e 只用键盘打完一夜 |
